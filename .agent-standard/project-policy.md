# M-LazyDesigner — Project Policy

**Scope:** local restrictions under the byte-identical shared AgentSkill root, current profile, and actual user authorization. It selects LazyDesigner product and domain owners; does not create an additional agent or automatically install any upstream original Skill.

## Current source work and held tests
- `Local` is the GitHub development authority; `main` changes only through explicit separate release/promotion permission. Do not create branches, dispatch GitHub verification Actions, run hosted CI, cloud agent/sandbox or deploy as a substitute for user-PC native acceptance.
- **Codex/local/native validation currently on hold** by the maintainer (2026-11-05). Complete coherent source architecture/reviews through connected GitHub without asking for repetitive localtest; author tests as source only, label NOT_EXECUTED.
- The mere presence of Blockbench, desktop control, Gateway or an MCP source does not prove a connected runtime or visual PASS. `LOCAL_PC_AGENT` requires genuine authorized execution against the user-PC checkout; `LIVE_BLOCKBENCH` needs connected native observation.

## Domain Skill ownership
- Preserve the existing **12** project Skills exactly: `lazydesigner-animation`, `lazydesigner-blockbench-development`, `lazydesigner-desktop-ui-design-development`, `lazydesigner-development-brief`, `lazydesigner-mcp-development`, `lazydesigner-modelling`, `lazydesigner-particle-reference-authoring`, `lazydesigner-pixel-art-authoring`, `lazydesigner-prompt-compiler`, `lazydesigner-reference-preparation`, `lazydesigner-skill-development`, and `lazydesigner-texturing`.
- Three new `oits-*` Skills own shared governance/source audit only. Do **not** replace `lazydesigner-development-brief` or `lazydesigner-skill-development`, or load every specialist; route actual product work via `docs/README.md`, `docs/04-system/skill-taxonomy.md` and current source. A domain implementation's nearest `mcp/AGENTS.md` and the distributed `distribution/authoring-AGENTS.md` retain their domain scope.
- Normal Bedrock authoring uses stable Gateway and **LazyDesigner Control** as the only asset router; Geometry and Texturing share AUTHORING, Animation uses the designated handoff. Use one active specialist: Geometry/rig/pivots/UV → modelling; atlas/material/PBR → texturing; animation/motion → animation. Do not preload Git repository tests in normal asset production.
- Reference preparation, pixel art, particle reference, Skill-system work, MCP/plugin development, and Svelte desktop UI each use their existing domain owners. For UI/UX discussions use current Svelte/HTML/CSS sources; do not treat a generative illustration as evidence of actual UI implementation.

## Product and proof boundaries
- LazyDesigner authors **Minecraft Bedrock Entity** visual assets (`.bbmodel`) and native Geometry/UV/Texture/Animation; it is not a general add-on/gameplay pack generator. Preserve existing Gateway/Runtime/Control contract, loopback security, user-approved asset persistence and Studio/Blockbench authority.
- Do not remove generated QA, face coverage, tool branches, sound/effect references, material fidelity or validation just to reduce tokens. Model visual and animation success require a matching native observation and user review or an explicitly approved alternative.
- Existing `CONTEXT.md`, `docs/05-operations/next-action.md`, `docs/04-system/implementation-map.md`, current source and active workstream remain authoritative. Do not invent proof or promote historical CI/Next.


## Related Lazy-family task routing

When an explicitly authorized task involves another Lazy Minecraft product, consult this repository's `README.md` **Related Lazy-family handoff** section to locate the actual artifact and evidence owner. This is a navigation pointer, not another agent/router. Read the other repository's current selected ref and own local policy only when the handoff is genuinely required. Preserve exact asset/world identity, edition/version, user approval, evidence tier and every local test/CI hold. A relationship never grants automatic transfer, cross-repository writes, native host access or gameplay approval.

Retain all actual stricter project rules, domain Skills, nested instructions, test holds, product source and private model data.
