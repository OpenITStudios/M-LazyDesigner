# Repository Knowledge Architecture — source-witnessed documentation graph

**Owner:** docs/04-system/knowledge-architecture.md (system-development navigation).
**Proof:** DERIVED / SOURCE_WITNESSED; not a second Runtime or documentation authority.

## Goal and ownership

The M-Lazy-Developer Graphify / Obsidian / Pele pattern is adapted to current LazyDesigner owners instead of copying its second Resource Catalog, Skill router or task manager. Paths in docs/ are already the explicit document IDs generated by mcp/lib/semantic/knowledge.ts; section content hashes and source-owner mappings are still owned by their existing modules. A renamed file changes its path ID and requires an authored link update and Git rename evidence; never invent a fuzzy alias.

Task → docs/README.md Router → exact authored document link and file:line witness → bounded directed trace → selected canonical document → existing source owner → existing semantic impact and targeted test owner.

## Graphify source-witness contract

- Registered resources are existing docs/*.md paths. README.md files are navigation routers, not newly elected semantic owners.
- Only resolvable, explicitly authored Markdown and exact repo-root Obsidian wikilinks become graph edges. Preserve duplicate authored occurrences and original file:line evidence. Fences, inline code, comments, image embeds, escaped links and fuzzy note-name matches cannot create edges.
- Missing targets become unresolved obligations. Unknown source/target yields UNKNOWN_RESOURCE; no path yields NO_PATH; limit yields DEPTH_LIMIT. Reverse traversal is opt-in; a reverse link never implies dependency or ownership.
- Default trace is directed, shortest, deterministic and limited to six hops. Scope and proof ceiling remain explicit.
- The audit shows documents unreachable from docs/README.md as review candidates, never automatic stale/retired deletion decisions.

## Obsidian, Pele, Mermaid

The CLI emits markdown with repository-root Obsidian wiki links and a Mermaid diagram. Obsidian is not installed and no vault is mutated. Pele (https://github.com/obsidianmd/pele) may render Mermaid in a separately authorized environment but is not invoked. Graphify here is the provenance-preserving architecture graph method, not a separately installed graph execution framework. Mermaid visualizes witnesses; it never creates them.

## Intended usage (when executable tool access is authorized)

From mcp/:

    bun run analyze:documentation-graph -- --audit
    bun run analyze:documentation-graph -- --trace docs/README.md docs/04-system/knowledge-architecture.md --format=markdown
    bun run analyze:documentation-graph -- --trace document:docs/README document:docs/04-system/implementation-map --max-hops=3 --format=mermaid

For source change impact use existing plan:affected; for TypeScript static imports use existing audit:reachability. Neither can prove actual Blockbench invocation. Tests and native verification remain NOT_EXECUTED while the user hold applies.

## Adoption and lifecycle

Add new canonical documentation under its present 01–05 domain, create one explicit Markdown router link, inspect the audited link witness and affected producer/consumer, and preserve Git history through moves. If a link is missing, repair the owning router rather than making a synthetic inferred edge. No external tool install, new Agent Skill, Control stage, Gateway tool, external graph service, persistent graph store, auto-merge or release.
