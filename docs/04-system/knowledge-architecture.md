# Repository Knowledge Architecture — source-witnessed documentation graph

**Owner:** docs/04-system/knowledge-architecture.md (system-development navigation).
**Proof:** DERIVED / SOURCE_WITNESSED; not a second Runtime or documentation authority.

## Goal and ownership

The M-Lazy-Developer Graphify / Obsidian / Pele pattern is adapted to current LazyDesigner owners instead of copying its second Resource Catalog, Skill router or task manager. Paths in docs/ are already the explicit document IDs generated by mcp/lib/semantic/knowledge.ts; section content hashes and source-owner mappings are still owned by their existing modules. A renamed file changes its path ID and requires an authored link update and Git rename evidence; never invent a fuzzy alias.

Task → docs/README.md Router → exact authored document link and file:line witness → bounded directed trace → selected canonical document → existing source owner → existing semantic impact and targeted test owner.

| Concern | Canonical implementation | Strict boundary |
| --- | --- | --- |
| Document resource identity, section hashes, authored link parsing | mcp/lib/semantic/knowledge.ts | No independent catalog/registry |
| Derived path graph, direction, witnesses, Mermaid/Obsidian export | mcp/lib/semantic/documentation-graph.ts | Navigation only; no code DEPENDS_ON inference |

## Graphify source-witness contract

- Registered resources are existing docs/*.md paths. README.md files are navigation routers, not newly elected semantic owners.
- Only resolvable, explicitly authored Markdown and exact repo-root Obsidian wikilinks become graph edges. Preserve duplicate authored occurrences and original file:line evidence. Fences, inline code, comments, image embeds, escaped links and fuzzy note-name matches cannot create edges.
- Missing targets become unresolved obligations. Unknown source/target yields UNKNOWN_RESOURCE; no path yields NO_PATH; limit yields DEPTH_LIMIT. Reverse traversal is opt-in; a reverse link never implies dependency or ownership.
- Default trace is directed, shortest, deterministic and limited to six hops. Scope and proof ceiling remain explicit.
- The audit shows documents unreachable from docs/README.md as review candidates, never automatic stale/retired deletion decisions.

## Obsidian, Pele, Mermaid

The CLI emits markdown with repository-root Obsidian wiki links and a Mermaid diagram. Obsidian is not installed and no vault is mutated. Pele (https://github.com/obsidianmd/pele) may render Mermaid in a separately authorized environment but is not invoked. Graphify here is the provenance-preserving architecture graph method, not a separately installed graph execution framework. Mermaid visualizes witnesses; it never creates them.

For source change impact use existing plan:affected; for TypeScript static imports use existing audit:reachability. Neither can prove actual Blockbench invocation. Tests and native verification remain NOT_EXECUTED while the user hold applies.


## AST Source Dependency and Knowledge Witnesses

The existing `audit:reachability` owner now has optional source-only projections:

- `--impact=mcp/lib/semantic/knowledge.ts` follows **reverse exact AST import** paths to potentially affected modules. Each edge retains importer, resolved dependency, import syntax, type-only/runtime-capable classification and `file:line:column`.
- `--trace=mcp/scripts/development/plan-development-context.ts,mcp/lib/semantic/knowledge.ts` explains a directed dependency route. Depth is bounded 1–6 and selection requires real inventoried files; missing paths remain `UNKNOWN_SOURCE`, not inferred owners.
- `--knowledge-id=knowledge:...` searches exact AST string-literal references and imported `selectKnowledgeSections` / `indexMarkdownKnowledge` call sites. Exact source references, generic API candidates and declaration-only evidence are **not** Runtime knowledge consumption. Test-only literals remain a separate evidence class. Catalog registration is not checked by this source-reference mode, and absence of a source witness is reported as `NO_SOURCE_WITNESS`, not an invented declaration.
- Resolved, uniquely registered **relative** AST imports are the only selected projection edges. Computed imports, unverified `require` calls, member `require`, non-relative packages, non-code assets and unregistered targets remain explicit exclusions/obligations, not `DEPENDS_ON` assertions. The pre-existing reachability summary's historic grouping remains intact and must not be mistaken for this stricter proof.
- The source graph is opt-in and separate from documentation relationships, Semantic Impact and the Runtime Capability Graph. Mermaid/Pele and Markdown output are derived source only and do not render SVG, install Obsidian or prove execution.

Examples, to run only after executable verification is reauthorized, from `mcp/`:

    bun run audit:reachability -- --impact=mcp/lib/semantic/knowledge.ts --max-hops=3 --format=markdown
    bun run audit:reachability -- --trace=mcp/scripts/development/plan-development-context.ts,mcp/lib/semantic/knowledge.ts
    bun run audit:reachability -- --knowledge-id=knowledge:docs/03-authoring/modelling/standard#geometry

An absent literal reference does not establish that a section was never dynamically loaded. A source code import or call is a navigation witness and not evidence of a tested feature, an accepted 3D model, an active Blockbench capability or an applied specific knowledge fact.

## Audited blind spots and proof limits

The source-level corrections narrow previous optimistic conclusions: no verified importer is `NO_PATH`, not `FOUND`; unresolved computed/unverified imports may yield `INCOMPLETE_EVIDENCE` where they can hide an affected module. Exact result limits do not imply truncation, and both total unresolved sites and displayed sample counts are retained. Scope is **MCP TypeScript-config and standalone `scripts/` JS**, not the entire Desktop/distribution repository. AST source imports never establish actual execution. Each newly inspected source witness carries the SHA-256 of its exact code text; the same file path/line at a different hash is not identical evidence. A self-source trace is explicitly `SAME_SOURCE_NO_IMPORT_EDGE`, not synthetic `FOUND`.

The source-only knowledge-candidate scanner now observes existing **Recipe** calls (`suggestRecipeKnowledge`, `resolveRecipeKnowledgeLinks`, `reviewRecipeKnowledge`, `prepareKnowledgeAwareRecipe`, `collectRecipeKnowledge`, `indexRecipeKnowledge`) only when value-imported from their canonical modules. These are still generic candidates and cannot prove that a specific Knowledge record was applied. Type-only imports do not become runtime knowledge candidates.

Documentation graph witnesses include a SHA-256 of the authored source bytes alongside `file:line`. This binds a link to document content, not to a Git commit, approved revision or tested execution. Fence markers hidden in HTML comments or multiline inline code cannot suppress real links or become synthetic sections. Cross-product graph coverage, exact-HEAD executable tests, Pele/Obsidian rendering, real-world knowledge consumption and native Blockbench acceptance remain unverified.
## Adoption and lifecycle

Add new canonical documentation under its present 01–05 domain, create one explicit Markdown router link, inspect the audited link witness and affected producer/consumer, and preserve Git history through moves. If a link is missing, repair the owning router rather than making a synthetic inferred edge. No external tool install, new Agent Skill, Control stage, Gateway tool, external graph service, persistent graph store, auto-merge or release.
