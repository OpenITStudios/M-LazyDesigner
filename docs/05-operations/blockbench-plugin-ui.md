# LazyDesigner Blockbench Plugin UI — product-value gate

Source authority: current `Local` implementation in `mcp/ui/panel.html` and `mcp/ui/index.ts`. This specifies **source-authored UI**, not verified installed-plugin behavior. Cross-surface navigation and UX acceptance belong to [Human Interface Contract](../01-product/interface-ux.md). In the native panel, keep the actionable Geometry checks above the optional Particle Studio form.

## Product rule: no nonproductive UI

The normal AI workflow uses the existing four-tool Gateway and canonical Runtime capabilities directly. The user only needs the native editor panel when it improves a specific **human decision or action**. The plugin shall not recreate Blockbench's Texture list, palette controls, Animation clip list or Timeline as trivial copies.

The docked human panel presents Runtime status, current project, actionable **Geometry checks** and the opt-in **Particle Studio** for a real in-editor particle authoring/preview workflow. The Geometry panel displays one actionable empty state at a time: open a project when none exists, or switch format when the active project is not Bedrock. The optional cleanup control is explicitly marked Advanced and retains native dry-run, UV risk and permission checks. A Runtime-failed status offers an explicit Reload LazyDesigner and Copy Error Details path; ordinary Blockbench editing remains separate from AI readiness. No empty Texture or Animation tabs are rendered; those native editing tasks remain in Blockbench while AI invokes the existing Gateway capabilities. Geometry/Texturing/Animation remain semantic authoring Stages, **not** human-panel navigation tabs. No second Gateway, route registry, progress engine, polling loop or screenshot-as-QA.

## Geometry Change Review — an AI-first human review, not a new editor

- This is a **post-edit** inspection of the *latest applied native Blockbench Undo entry*; it does **not** invent an AI proposal, show a pre-Apply approval gate, or distinguish AI changes from manual changes.
- `mcp/ui/geometryChangeReview.ts` reads only `Undo.history` snapshots; native `UndoEntry.before.elements` and `UndoEntry.post.elements` are the source of before/after truth. It never calls `Undo.initEdit`, mutates a Cube, or creates an undo entry.
- Skip selection-only history entries; **do not** skip a later Texture/Animation edit to present an old Geometry edit as current. If the most recent authored edit has no Cube snapshots, disclose this rather than fabricate a result.
- Compare named supported fields: `name`, `from`, `to`, `origin`, `rotation`, `inflate`, `box_uv`, `uv_offset`, `mirror_uv`, `autouv`, `visibility`, and bounded per-face UV/material mapping. Compare only finite/valid fields present in both snapshots; missing data is not a proven change.
- Show at most 8 changed Cubes, but report the exact changed count. The review can inspect up to 2500 saved Cube snapshots and otherwise fails explicitly. Added and removed Cubes have distinct labels; removed Cubes cannot be located.
- `Locate Cube` verifies plugin generation, exact Project object, current Undo revision identity and exact Cube UUID using the existing native `select()` + `showInOutliner()` navigator. The existing Runtime-native queue serializes this against AI operations. Native selection can change; authored state cannot.
- Any new edit/Undo/Redo/project switch/hot reload invalidates the review. Selecting a Cube does not invalidate it. The UI does not offer a duplicate Undo action or false AI-completion progress.
- This is a **supervision and location feature**, not Geometry repair. A true pre-Apply AI-proposed correction still needs an explicit, canonical proposal-to-UI transport and native acceptance; do not label this review as a functioning approval workflow.

## Measurable value requirement

On a disposable asset with at least 100 Cubes, run the same AI geometry edit and compare time/clicks required to identify and inspect the changed Cube(s) using native history/outliner alone versus Geometry Change Review. Require correct UUID targeting, exact before/after values, zero authored mutations/Undo entries during review, and a demonstrable improvement in inspection speed. If no measurable benefit, remove the feature rather than adding decorative status panels.

## Canonical Geometry evidence and issue contract

- Reuse `geometryHygieneRuntime()` and `rigGraphRuntime()` as-is; these already wrap `analyzeGeometryHygiene` and `analyzeRigGraph`.
- Only present **targeted** findings from real `degenerate_cubes.examples`, `duplicate_bone_names.examples[].groups`, and `box_uv_subunit.examples`. Every issue contains the actual native UUID, type, name and a cautious description.
- Intentionally omit tiny precision drifts from the primary findings list; keep them in optional counts. Avoid treating zero-thickness design panels or coincident pivots as automatic defects.
- Limit visible findings, disclose truncated examples, and never infer visual PASS from a clean bounded scan.
- Locate revalidates the project/generation and current UUID-backed issue under the shared `runRuntimeOperationExclusive` queue. Reject stale, missing and duplicate UUIDs. Use the native `select()` and `showInOutliner()`, not duplicate selection or viewport code.
- Selecting a finding should **not clear the issue list**. Geometry edits, project changes, Undo, Redo and plugin reload invalidate the analysis. No model mutation or Undo entry is created by locating an object.
- This does not claim the AI's previous job finished successfully; no inferred AI receipt, status or fake progress.

## Existing Safe Cube Cleanup invariants

- Before Apply, recheck project/format, Geometry Stage, exact selected UUIDs, parent/UV/transform state and fresh canonical dry-run result.
- Reject incomplete UV inventory, mapped painted-face stretch, Box UV template risk, stale plan, concurrent native edit, retired generation and duplicate Apply.
- Apply only via the canonical `manage_cubes` native executor under the shared Runtime operation queue. Never replay an ambiguous mutation.
- A successful source-level receipt is **not** a visual reference-accuracy PASS.

## Acceptance criteria: minimum for any "useful tool" claim

1. **Change review:** Construct a disposable Bedrock asset with one real Cube transform edit, one rename, one UV edit, one deleted Cube, and one Texture-only edit. Review shows actual native before/after snapshots, names the latest edit without inferring AI origin, and never guesses missing data. Selection-only Undo entries are ignored; later non-Geometry edits must not surface an outdated Geometry edit.
2. **Fixture / locator:** Construct disposable Bedrock asset with two degenerate Cubes, distinct duplicate-named Groups and a sub-unit Box UV Cube. Every exposed finding is anchored to the exact UUID; clicking **Locate in Outliner** selects and reveals the correct native node, not the first name match.
3. **No mutation by inspection:** Inspecting and locating must not change transforms, UVs, animation curves, textures, dirty state or Undo history; editor selection changes are intentional and visible.
4. **Context isolation:** Switching project, editing the source Cube, deleting/replacing an UUID, or plugin reload invalidates stale findings. Queue a simultaneous AI edit and user locate; they must serialize without stale replay.
5. **Review honesty:** Limit and truncation are disclosed; no visual or export acceptance is inferred from technical checks.
6. **Cleanup:** Preview has no Undo; explicit Apply has one Undo unit and correct Redo. Block mapped-texture/Box UV hazards; re-open/save preserves the asset.
7. **Normal UX:** Docked panel, Geometry actions and disclosures are keyboard-operable; no empty tabs, redundant palette/clip lists, abandoned dialogs/actions after reload, or raw MCP schemas in the human panel.
8. **Value benchmark (not yet run):** Measure time and clicks to find an exact problem Cube in a 100+ Cube asset with and without the Issue Navigator. Keep the feature only if it demonstrates an objective gain without mistaken targets.

## Particle Studio — source-authored human experience (2026-11-06)

Particle is not a new Authoring Stage, Gateway tool, resource-pack assembler, texture pipeline, or separate renderer. The optional Studio appears below Geometry checks in a **collapsed native details disclosure**. The summary also reports a currently playing preview, without claiming that observed rendering has passed visual review. A new unsaved draft shows **Reset Draft**, restoring its starting preview without changing a file; a previously saved effect shows **Revert Changes** and **Save Changes**, matching the existing canonical Save transaction and preview reset. The user sees which controls need a saved .bbmodel, and a blocked Animation stage is explained in ordinary task language. Its summary indicates Bedrock/Animation readiness, a loaded effect or an unsaved draft even while the controls are hidden. The summary also distinguishes a saved effect with unsaved changes, preview playback, and preview/file errors, prioritizing attention above Stage eligibility so errors cannot disappear behind a Stage switch. The short error notice remains visible outside the closed disclosure; when opened, the same error is presented in detail even if the form is Stage-gated. A native details selector ensures only one error alert is visible at a time. A read-only, Stage-blocked or unsaved model has a nearby explanation rather than an unexplained disabled control. Expand it to use the unchanged native New/Open, Preview, Save, Attach and diagnostics actions; collapsing hides controls but does not reset an in-memory draft, write a file or stop a preview. A project switch, Stop or plugin teardown still uses the existing Runtime-owned lifecycle and invalidation rules. This is a source-authored presentation contract, not native usability proof.

- Available in the **Animation Stage** for Bedrock Model projects on Blockbench desktop. A new effect starts as a **memory-only draft**, can be previewed before the model is saved, and does not create a file. Persisting an effect requires a saved model; only then is it written via the existing atomic `manage_particle` transaction into the Bedrock Resource Pack's `particles/` folder when the model is unambiguously under `models/` or `models/entity/`; otherwise it uses a `particles/` sibling of the saved model. No Behavior Pack, manifest or client-entity mapping is created.
- A simple effect can be created from an existing Bedrock preset using the vanilla particle texture. The panel exposes emission, speed, size, lifetime and tint; it edits only changed fields of the loaded document through the existing `manage_particle` transaction. Advanced/Molang-owned values are displayed as locked controls, not overwritten with fake defaults.
- Existing `*.particle.json` files in both canonical and previous model-adjacent `particles/` folders remain discoverable (64 visible results maximum), with explicit source labels for previous locations. File discovery uses supported Blockbench ScopedFS `readdirSync({withFileTypes:true})` entries to reject symlink and non-file entries; `lstatSync` is not exposed to plugins. File Open/Save validates the exact project-owned path independently of the 64-item UI result limit, so a previously opened particle remains saveable even if the listing is truncated. New effects use the canonical folder; collisions against either location fail before overwrite. There is no recursive asset crawl or new filesystem watcher. The studio checks the source text before edits, rejects stale externally changed files and preserves loaded files at their original location.
- Studio offers three additional opt-in quick controls (opacity, sphere/disc radius, and vertical acceleration) using lossless, numeric-only mutations. Gradient/MoLang-owned fields remain read-only. They reuse the existing one-emitter, coalesced slider preview, subject to the new authoring preview budget.
- Studio preview uses the existing Blockbench Wintersky scene/Emitter (native host, no second renderer). **Live slider edits** compile an isolated Wintersky Config from the unchanged source JSON, retaining advanced Molang/events/curves and unknown fields. The native Animation registry is not required to preview, and no filesystem read occurs per slider event. Native Animate mode is entered only in response to explicit Create/Open/Replay. The preview emitter and private texture are owned and disposed on replay, project/mode change or plugin teardown. Loader invocation and observed particle count are **not** visual acceptance.
- Slider/color/locator changes are event-driven, coalesced at a bounded interval during dragging, and serialized through the existing Runtime operation queue. Stale queued previews are retired on project change, save, Stop, new/open effect and plugin reload. Unsaved changes can be discarded; replay uses the current unsaved draft rather than requiring an early save. **New Effect** and **Open** check whether the existing draft has never been saved or a saved effect has unsaved edits; if so, they ask for explicit confirmation *before* canceling queued previews, stopping a live emitter or replacing the draft. Cancel leaves the live draft and preview intact. An unchanged saved effect does not require confirmation. The panel explains that switching Blockbench projects discards unsaved in-memory particle edits, while saved particle files are not deleted. This is a browser-native user-click confirmation, not a new managed dialog, queue or storage layer.
- Blockbench Animate mode must be active for WinterskyScene to be mounted and billboard updates to work. Do not mutate `Animator.particle_effects[path].config` for unsaved drafts or create a second scene/renderer. A preview is only a visual hypothesis until actual viewport evidence exists.
- File Save requires the **canonical verified particle write receipt**, including the matching atomic `writes[]` entry, not merely a plausible `wrote_to_path` string. A refused or failed write keeps the current live preview intact and does not falsely mark playback stopped; preview teardown happens only after confirmed persistence. File Save and native preview are independent success criteria: a saved JSON is not reverted or reported as uncommitted merely because rendering is unavailable. Only Attach first registers an effect with Blockbench's native Animation registry and invokes the canonical Animation effects tool at the selected playhead. **Save refreshes an effect already registered by Animation** so atomic file replacement cannot silently leave old visuals active; if that native refresh fails, the committed-file status remains correct and the panel reports a bounded warning. Ambiguous short names fail closed before keyframe mutation; the user still selects an Animation.
- A missing custom PNG, native/Wintersky incompatibility or an unavailable emitter is surfaced as an actionable error; this UI does not author bitmaps or bypass the Stage/Gateway readiness boundary. Failed preview from New/Open reports **Preview unavailable** without dropping the memory draft or loaded file. If canonical file Save succeeds but a subsequent standalone preview fails, the status explicitly states **Particle file saved, but preview unavailable** rather than inventing a failed write. Changes to the host Blockbench mode truthfully report that the standalone preview stopped.
- **Check Preview** performs an explicit, bounded read-only source/texture preflight: validate the JSON, detect changed/missing source files, resolve custom PNG paths relative to the nearest canonical `particles/` parent (without traversal), and distinguish a missing custom PNG from renderer placeholder/pending texture and no active particles. Vanilla atlas references use the native built-in texture instead of requiring a local PNG. This is not automatic scanning, bitmap generation or pixel-visibility proof.
- Known upstream risks for live acceptance: Blockbench issue #2377 (stale texture reload even in 5.2.2), #3822 (texture placeholder after Animation save), and world/entity/locator space differences. The new read-only diagnostics do not pretend to measure rendered pixels.

Button gating is a UI guard only: the native file/Stage/Animation preflight remains the authority. Source-authored regression guards cover the summary/error/disabled-state contract; an installed Blockbench keyboard, screen-reader and viewport review is still required before claiming UX acceptance.
